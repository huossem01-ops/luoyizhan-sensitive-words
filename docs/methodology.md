# 构建方法

## 1. 目标与边界

`term` 的目标是中文词和固定/常用短语，不是完整句子。项目不通过添加时间、地点、人物或程度副词制造变体；语义多样性必须来自不同概念节点。

旧的规则/LLM 扩写数据已经移入 `data/legacy_generated/`，只供失败分析，不参与正式召回和统计。

## 2. 当前 MVP 流水线

1. 在 `config/seeds.yaml` 维护少量高精度种子，并按恋爱核心、对象关系、校园恋爱、表白追求、约会、亲密行为、单身脱单、恋爱历史、婚恋、社会比较分组。
2. 从腾讯 AI Lab 中文词/短语向量词表读取候选及 200 维向量。
3. 对每个候选计算所有在词表种子的余弦相似度。
4. 综合分数为 `0.6 × 最大种子相似度 + 0.4 × Top-3 种子平均相似度`。
5. 保留较大的候选池，执行词形过滤和规范化去重，再取 Top 5,000。
6. 输出完全重复、规范化重复和字符近重复报告。
7. 输出长度、类别、分数分布，以及随机样本和指定排名附近的人工审核样本。

完整向量源和轻量镜像的区别见 `data_sources.md`。

## 3. 词条过滤

自动过滤只做可解释的高精度判断：

- 过滤 URL、HTML、纯数字、明显句末标点和低中文字符占比词条；
- 过滤带明显主语/时间地点开头或句式结尾的完整句子；
- 默认接收 2–16 字词条，30 字以上硬性禁止；
- 仅作机械规范化：Unicode NFKC、大小写、繁简转换、空白和外围标点处理；
- 不把“谈恋爱”和“谈过恋爱”这类语义不同表达强行归并。

最终目标长度结构仍为：2–6 字约 45%，7–12 字约 40%，13–20 字约 14%，21–30 字最多 1%，超过 30 字为 0。MVP 的自然召回分布用于判断是否需要分层抽样，而不是通过扩写补齐配额。

## 4. 去重与人工审核

- 完全重复：原始 `term` 相同。
- 规范化重复：机械规范化结果相同。
- 近重复候选：通过稀有字符 bigram 建索引后，再结合编辑距离和字符 n-gram 相似度报告。

近重复检测不会自动删除主题相近但语义方向不同的表达。自动召回也无法可靠排除人名、作品名、品牌名和语境依赖词，因此 `reports/random_samples.csv` 与 `reports/manual_review_samples.csv` 必须进入人工审核。

## 5. 等级说明

当前 `semantic_level` 按 Top 5,000 内的相似度分位数暂定：最靠前 10% 为 5，随后 20% 为 4、30% 为 3、30% 为 2、最后 10% 为 1。它只描述机器召回的相对排序，不代表人工确认的触发强度。人工标注协议稳定后才能替换这一临时规则。

## 6. 后续扩展门槛

在 Top 5,000 的随机抽检准确率、错误类型和类别覆盖没有明确结论前，不扩到 48,000。未来可替换为官方完整腾讯向量，并可加入 BGE 类中文文本向量做第二阶段重排；任何升级都必须保留源版本、参数和可复现实验报告。
